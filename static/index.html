INCIDENT RESPONSE GUIDE

Actionable Security
Playbooks.

Step-by-step containment procedures if you suspect compromise, leaked credentials, or fraudulent transactions.

CRITICAL SCENARIO

I Shared an OTP or Password

  1. Freeze immediate access: Call your bank's emergency debit/credit card blocking hotline or use your bank app to freeze netbanking immediately.
  2. Change primary passwords: Reset the password for that account and any other services sharing similar passwords using a different, clean device.
  3. Revoke active sessions: Go to the security settings of your account and click "Log out of all devices" or revoke active sessions.
  4. Report the incident: In India, dial 1930 (National Cyber Crime Reporting Helpline) or file a report at cybercrime.gov.in within the golden hour.
PREVENTATIVE

I Clicked a Suspicious Link

  1. Do not enter any information: Close the browser tab immediately. Never input credentials, payment details, or phone numbers.
  2. Disconnect network if file downloaded: If an `.apk`, `.exe`, or profile configuration began downloading, turn off Wi-Fi/mobile data instantly.
  3. Clear browser cache & cookies: Clear site data and cookies for that specific domain to prevent credential replay tokens.
  4. Scan device with reputable AV: Run a full system antivirus scan (e.g. Play Protect on Android, Windows Defender, or Malwarebytes).
DEVELOPER DEFENSE

I Committed a Secret / API Key

  1. Invalidate immediately: Do not just push a commit deleting the key! Go to the provider console (AWS, Stripe, OpenAI, Gemini) and revoke the secret immediately.
  2. Audit recent API logs: Check cloud audit logs for unauthorized billing spikes or suspicious access during the exposure window.
  3. Clean git commit history: Use tools like `git-filter-repo` or BFG Repo-Cleaner to completely purge the secret from previous commit objects.
  4. Adopt environment secrets: Migrate to `.env` with `.gitignore` or a dedicated secrets manager like Google Secret Manager or HashiCorp Vault.

ZERO-LEAKAGE PROMISE

Client-First Privacy Architecture

CyberGuard Hub is engineered on the principle that digital safety tools must never become attack surfaces themselves:

Zero Ingestion Persistence

The server processes your messages, links, code, and files strictly in RAM for the lifetime of the request. No database saves your submitted raw content.

Offline Link Heuristics

The URL analyzer never visits or curls target domains. It performs static syntactic, lexical, and character distance audits only.

Sanitized AI Context

When Groq or Gemini explanations are generated, the server transmits only abstract rule labels and sanitized scores—never your original message or code.

Strict Opt-In Vision

Image files are only sent to Google Gemini if you explicitly check the opt-in box on that specific upload.

Reminder: This is a hackathon safety prototype. Always verify critical requests via official hotlines.
